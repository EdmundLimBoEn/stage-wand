Design: Stage Wand — iPhone as pocket clicker, air-pointer, and trackpad for macOS

Generated by /office-hours on 2026-09-18 Branch: none (greenfield, not yet a git repo) Repo: fable-5.1-build-day (local) Status: APPROVED 2026-09-18 (revision 3: all-native pivot after D8; gyro demoted to stretch; handoff to a fresh coordinator chat) Mode: Builder (build day, 60-minute MVP, was 2 h) Working name: "Stage Wand" (Codex's phrase, rename freely)

Problem Statement

On stage you want to advance Keynote slides with the phone still in your pocket (hands free for gestures), then pull the phone out and drive a live software demo: cursor, clicks, scroll, Escape, arrows, and switching spaces, without walking back to the laptop. Edmund: "for most of the thing it should be volume up and down for changing slides, freeing up my hands for gestures ... then ... use the mouse, with common keys like Left and Right arrows, left/right click and escape" and "trackpad mode so i can also like scroll around and stuff, 3 finger swipe, and generally control my mac from my phone."

What Makes This Cool

  • Phone stays in your pocket. Volume up = next, volume down = previous, with the screen locked. Haptic tick on every press.
  • Pull it out, unlock, ARM: thumb a joystick or use the whole screen as a trackpad with scroll and 3-finger swipes between spaces, and the real macOS cursor follows. Stretch, only if time is left: hold-to-aim gyro air-pointer.
  • Both ends are native Swift. The Mac finds the phone via Bonjour; no QR, no tunnel, no web page, no HTTPS.

First principles

A remote is three irreducible parts: an input surface, a channel, an injector. Going native on both ends collapses the channel to Apple frameworks (NWListener + NWProtocolWebSocket on the Mac, URLSessionWebSocketTask on the phone) and makes the input surface richer (hardware buttons, CoreMotion, haptics). The hand-rolled WebSocket server, the Cloudflare tunnel, the HTTPS requirement, and the QR from revisions 1-2 are all deleted. Hostile venue Wi-Fi is solved with zero code: the Mac joins the phone's hotspot.

Hard constraint that forced the pivot

iOS Safari never reports hardware volume presses to a web page and media volume is read-only on iOS. Volume-as-clicker is only possible in a native app that keeps an audio session alive and observes AVAudioSession.outputVolume. This is a well-known workaround for personal builds, not App Store material. Accepted (D8: "yes its supposed to be all native as much as possible").

Constraints

  • 60 minutes wall-clock, one human + as many parallel agents as there are files (Fable 5.1 coordinates, Astra writes the hard code; PLAN.md is the standalone handoff).
  • Mac: macOS 27, Xcode 27, Swift 6.4; deployment target macOS 14. Phone: iPhone 13 Pro Max, iOS 17+ target, free-provisioning signing (one "Apple Development" identity present, team U968QPQQ67; apps expire after 7 days, reinstall from Xcode).
  • iOS project generated with XcodeGen (installed) from project.yml; Mac app is a SwiftPM executable. Shared Protocol.swift compiled into both.
  • Zero third-party packages anywhere.

Premises (revised for the native pivot)

  1. Two native apps, one shared protocol file. Mac: SwiftUI menu-bar app, activation policy .accessory so Keynote keeps focus. iPhone: SwiftUI app with background-audio capability.
  2. Channel: WebSocket over LAN. Mac advertises Bonjour _stagewand._tcp on port 8787 (fallback 8788-8790); phone browses and auto-connects, with manual host:port in Settings as fallback. Venue Wi-Fi fallback: Mac joins the phone's hotspot (same code path).
  3. Slides: volume up/down → Right/Left arrow to the frontmost app, works with the phone locked. Pocket guard for everything else is the lock screen plus an in-app ARM state: pointer and gestures only send while armed.
  4. Pointer mode in v1: Trackpad only. Joystick (stick offset → cursor velocity) and then Gyro (hold-to-aim, CMMotionManager rotationRate → relative deltas) are stretch goals, built only if Wave 2 finishes by minute 45. Trackpad = 1-finger move, tap left click, 2-finger tap right click, 2-finger drag scroll, 3-finger swipe left/right → Ctrl+←/→ switch spaces, 3-finger swipe up → Ctrl+↑ Mission Control). Keys: Left, Right, Esc. Clicks: left, right.
  5. Trust boundary: 4-digit pairing code shown in the Mac menu bar, sent as the first frame; phone remembers it. A valid code always displaces the current peer (a dead socket after locking the phone must never lock you out). Server pings every 3 s, drops after 6 s without pong. Kick rotates the code.
  6. Manual steps: Accessibility permission (re-prompts after rebuilds), firewall Allow on first bind, Xcode team selection once + "Trust developer" on the phone once, iPhone plugged in for install, both devices on the same Wi-Fi or hotspot.
  7. Riskiest pieces, in order: (a) volume observer while locked (silent loop + outputVolume KVO + reset-to-0.5 so presses at max/min still register), (b) iOS signing/install friction, (c) CGEvent coordinate handling. (a) gets Astra at high effort and a device test at minute 60. If (a) fails, on-screen NEXT/PREV buttons still ship.

Landscape (in-distribution, no web search run)

Keynote Remote (Keynote only), Remote Mouse / Unified Remote (LAN, generic, no pocket volume clicker, no gyro), KDE Connect (Linux-centric). Volume-button clickers exist as camera-shutter hacks, not as presenter tools. Nothing here is novel technology; the novelty is combining pocket clicker + air-pointer + trackpad in one native pair.

Cross-Model Perspective (Codex, gpt-6-astra, low reasoning, on revision 1)

Adopted and still valid after the pivot: hold-to-aim clutch; relative rotationRate mapping (never absolute orientation); "cursor reliability is the payoff, slides are the on-ramp"; disjoint-file agent split; freeze the contract before fan-out. Its WebSocket-parser and tunnel advice is now moot.

Adversarial review (Claude Opus subagent, revision 1): 7/10

Findings that survive the pivot and are baked in: stale-controller liveness + displace-on-valid-credential; accessory activation policy; firewall prompt and Auto-Lock as manual steps (Auto-Lock no longer matters for slides, since volume works locked; it still matters for pointer sessions); cursor clamping owned by Input; port fallback; server-side rate drop > 100 msg/s; MainActor hop contract; gyro axes gamma→dx, beta→dy (CoreMotion: rotationRate.y → dx, rotationRate.x → dy for a phone held upright, signs tuned on device); CGEvent has no relative move (read location, add delta, clamp, post absolute with delta fields set); TCC re-approval after each rebuild is a fact, ad-hoc codesign does not fix it; latency is a goal, not a gate. Findings about the hand-rolled WS parser, tunnel, HTTPS, and token-in-query are moot. Revision 3 will be re-reviewed once.

Wire protocol (frozen at minute 15; source of truth Shared/Protocol.swift; JSON text frames)

Phone → Mac

{ t:"auth",   code:string }                        // first frame within 2 s or the server closes
{ t:"move",   dx:number, dy:number }               // screen px, +x right, +y down, |d| ≤ 400; ≤ 60/s client, > 100/s dropped server-side
{ t:"click",  b:"left"|"right" }
{ t:"scroll", dx:number, dy:number }               // pixel units
{ t:"key",    k:"left"|"right"|"esc" }             // Left 123, Right 124, Esc 53
{ t:"chord",  k:"spaceLeft"|"spaceRight"|"missionControl" }   // Ctrl+←, Ctrl+→, Ctrl+↑

Mac → Phone

{ t:"status" }                                     // on auth success (Reply enum with hand-written Codable, not a struct with a `let t`)
{ t:"bye", reason:"kicked"|"displaced"|"badauth" }

Transport: NWListener with NWProtocolWebSocket.Options(autoReplyPing: true) on plain TCP; Bonjour via listener.service = .init(name: hostName, type: "_stagewand._tcp"). Phone: URLSession.shared.webSocketTask(with: ws://host:port/), NSAllowsLocalNetworking in Info.plist. All Session/Input access hops to MainActor (Swift 6 strict concurrency).

Data shapes (named before code)

  • Mac Session: peer: String? (nil = waiting); displace or ping timeout replaces or clears it; Kick → rotate code → nil.
  • Phone Link.State: searching, connecting(host), enterCode, authed, disconnected, localNetworkDenied; every UI element reads this one enum. Link buffers up to 8 key/click/chord commands while not authed and flushes on authed.
  • Phone PointerMode: enum { trackpad } (joystick, gyro cases added only if a stretch lands) persisted in @AppStorage; armed: Bool is NOT persisted and resets to false on background.
  • Command is one Swift enum used by both ends; Input.apply(Command) is the only place that touches CGEvent.

Input mapping (mac/Input.swift)

No relative move in CGEvent: read CGEvent(source:nil)!.location (CG space, top-left origin; never mix with NSEvent.mouseLocation), add delta, clamp to the union of NSScreen.screens frames converted to CG space, post .mouseMoved at the absolute point with mouseEventDeltaX/Y set. Clicks: down+up pairs. Scroll: CGEvent(scrollWheelEvent2Source:units:.pixel, wheelCount:2, wheel1: dy, wheel2: dx). Keys: keyDown+keyUp at .cghidEventTap. Chords: same with .maskControl flags. Spaces switching needs the default Mission Control shortcuts enabled (System Settings → Keyboard → Shortcuts → Mission Control), noted in README.

Volume clicker (ios/Volume.swift)

The silent player must be actively playing, not merely the session active, or the buttons control ringer volume and no KVO fires; restart on interruption and route change. The MPVolumeView slider reset is treated as expected-to-fail on modern iOS: set 0.5 once at start, attempt re-nudges while foreground, accept the at-limit dead zone as shipped behaviour. AVAudioSession category .playback, options [.mixWithOthers], active; AVAudioPlayer looping a bundled 1 s silent file at volume 0.01 so the session stays alive with the screen locked (UIBackgroundModes: audio). KVO outputVolume: increase → key right, decrease → key left, debounce 150 ms, ignore the change we cause ourselves. After each press, set the system volume back to 0.5 through a hidden MPVolumeView slider so presses at max/min still register. Side effect: the ringer/media volume sits at 50% while the app runs; documented. If iOS 27 blocks the slider hack, the fallback is "only works when volume is not at the limit", and on-screen NEXT/PREV remain.

Pointer modes (ios)

  • Gyro (STRETCH, only if ahead at minute 95): CMMotionManager.startDeviceMotionUpdates at 60 Hz. Phone upright aimed at the screen: rotationRate.y → dx, rotationRate.x → dy (rad/s), scaled sens * dt * k, dead zone 0.035 rad/s, EMA 0.6, clamp 60 px/frame, emitted only while HOLD TO AIM is pressed. Invert toggles in Settings; signs confirmed on device at minute 95.
  • Joystick (STRETCH): stick offset normalised to [-1, 1], cubic curve, velocity up to 1200 px/s, tick at 60 Hz while offset > dead zone.
  • Trackpad: UIGestureRecognizers. 1-finger pan → move (cssDelta * gain, gain 2.0 × sensitivity); 1-finger tap → click left; 2-finger tap → click right; 2-finger pan → scroll (natural direction); 3-finger swipe left/right/up → chord. ARM must be on for all of it.

Stage hardening

  • .accessory on the Mac; popover never activates the app; verify arrow keys still reach Keynote with the popover open.
  • AX: prompt on launch, red/green in menu, re-check 2 s. Expect re-approval after every rebuild; stop rebuilding at minute 110.
  • Firewall Allow on first bind; re-prompts after rebuild.
  • Phone lock: background audio keeps the process AND the URLSessionWebSocketTask alive, which is what makes the pocket clicker possible; this is the Wave 2 device pass/fail. If iOS does suspend the socket anyway, unlock → reconnect displaces within 3 s and buffered key presses flush. Volume → key bypasses ARM.
  • Wi-Fi: same network, else Mac joins the phone's hotspot. Manual host:port in Settings if Bonjour is blocked.

Success Criteria

  • Phone locked in pocket: volume up/down advances and rewinds Keynote on the first press, with a haptic.
  • Unlock, ARM: in each pointer mode the real cursor moves; left/right click a real window; trackpad scrolls a web page; 3-finger swipe switches spaces.
  • ← → Esc reach the frontmost app.
  • Lock/unlock the phone: it is back in control within 3 s without touching the Mac. Kick rotates the code and evicts.
  • Rehearsed once on venue-style Wi-Fi (or hotspot) end to end.

Glossary

  • Injector: the code that turns a message into a real OS input event (CGEvent).
  • ARM: in-app toggle; pointer and gesture commands only send while armed. The lock screen is the pocket guard.
  • Clutch: HOLD TO AIM; gyro only moves the cursor while held.
  • Chord: a modifier+key combo sent as one command (Ctrl+← etc.).
  • Displace: a new connection with a valid pairing code replaces the current peer.

ADRs (one line each)

  • ADR-1 All native (Swift on both ends) over a web remote: volume keys are impossible on the web; native deletes the WS parser, tunnel, HTTPS, and QR.
  • ADR-2 Bonjour + manual host:port over QR/tunnel: LAN discovery is one line each side; hostile Wi-Fi is solved by the phone's hotspot, not code.
  • ADR-3 NWProtocolWebSocket + URLSessionWebSocketTask over raw TCP: Apple owns framing, ping, and close on both ends.
  • ADR-4 Pairing code + displace-on-valid + Kick rotates, over token/PIN prompts: never locks the presenter out after a dropped socket; LAN-only exposure.
  • ADR-5 Volume via outputVolume KVO + silent loop + slider reset: the only route to pocket presses; personal-build acceptable.
  • ADR-6 Pointer modes (trackpad, joystick, gyro as stretch) behind one PointerMode enum and one Command stream: the Mac never knows which mode produced a delta.
  • ADR-7 Accessory activation policy: a menu bar app that activates steals Keynote's focus and silently breaks keys.

Rejected: replace joystick with gyro (Edmund cut gyro explicitly; joystick stays the first stretch); NSAllowsLocalNetworking does not cover IP literals (IP literals are exempt from ATS entirely, so LAN ws://192.168.x.x works regardless); two bursts of three (Edmund asked for maximum fan-out; two-burst fallback documented for overload errors); drop ws-smoke.ts (it is the only check for the Mac server before the iOS shell lands).
